## 0. なぜこれをやるか —— 資産は五つ

### 「同じことをやってる人はいっぱいいる」は、正しい

| やっていること | 先行 |
|---|---|
| 塔を畳む(機械を程式に特殊化) | **Futamura 射影**(1971)/ **PyPy·RPython** / **GraalVM Truffle** |
| 所有 | **Rust**、その前に Cyclone・線形型・region(Tofte–Talpin)、近くは Vale・Verona・Austral |
| 種から世界を計算する | **demoscene / .kkrieger** |
| 1 ファイル自己完結・wasm 埋め込み | single-file HTML app の系譜 |
| LLVM を避けて自分で機械語を吐く | **Zig の self-hosted backend** / **Jai** / 遡って **Forth** |

🔴 **「この言語が優れている」という主張はしない。** 事実に反する。
◆ そのうえで実際に持っている資産は五つ。**言語そのものは、その中に入っていない。**

| 資産 | 何であるか | 現在地 |
|---|---|---|
| **① 契約** | 実行の線が **データで書いてある**(14-op / 値モデルの整数域 / object tag 表 / engine seam) | ✅ ⚠️ 育成場に住んだまま |
| **② 秤** | 外した見立てを**型として残す**測り方 | ✅ 五度生えた。⚠️ 明文化されていない。⚠️ **ms は跨いで比べない**(§1) |
| **③ アプローチ** | 一本に育てず、**所有の対象を変えて分岐**させ、器官(koinon)を共有する | ✅ 五体で実演中 |
| **④ 共作者** | 契約がデータだから、**外の体が言語を触らずに道具を足せる** | ✅ 段E〜H が実証 |
| **⑤ 投影** | 一つの substrate を面を替えて出す(ASCII / canvas / WebGL / HTML / PNG / DOM) | ✅ 四度生えた |

段E(特殊化)・段F(x86-64)・段G(wasm)・段H(engine seam)は **melon / kokkos / ptyx を一行も触らずに書けた**。
読んだのは `machine.json`・`bench_host.json`・`enc_expr` の tag 表だけ。⇒ **①と④は同じ性質の表と裏。**

そして小さい言語が死ぬ理由はほぼ常に**エコシステム**。melon engine の三原則(状態は言語 / 入力は source
非依存の event / 出力は画素でなくデータ)は、実は**「読み手がエージェントなら、その穴が浅くなる」**という主張。
⇒ **2016 年に無謀だったことが、2026 年には無謀でない。** 可能性の一番硬い根拠はここだと思う。

▲ **正直なリスク**: **「言語」が正しい単位でないかもしれない** —— 実際に価値が出たのは言語より
**①契約 と ②秤** だった。成果物はコンパイル基盤かもしれない。⇒ 居心地は悪いが、そう見えている。

### 1-2. 🔴 反証テスト —— 「407x は整数ループの数字だろう」を壊しに行った

**予想は `probe_emit.py` の冒頭に、撃つ前に書いてある**(git が日付を持つ)。

- **407x は整数ループの数字ではなかった。** 閉包 **411** / cons **426** / 整数ループ **407** ——
  **値の種類にほぼ依らない**。塔(機械を解釈する厚み)は値の形と無関係なので、畳めば同じだけ消える。
  時間で見ても段E は床D の **339〜632x**(同一走行内の比)。⚠️ この幅は四本 ×2 標本の実測 —— **安定していない**。
  ⚠️ 三十八段で床D を 1.43x 速くしたので、この比は **646〜740x から縮んだ**。
    ◆ 縮んだのは塔が厚くなったからではない —— **分母が正しくなった**。命令数の比(407x)は 1 も動いていない。
- **閉包は消えた。** 呼び先が静的に一つに定まる(= escape しない)なら inline で丸ごと消え、**wasm 107 B** まで届く。
- **確保の 99.2% は *インタプリタ自身の* 確保だった。** cons 主役で 39,473 → **300 セル**。
  残った 300 は **list の実体そのもの**(消せない。それがデータ)。
- ⚠️ **わたしの予想は四度目に外れた** —— 「cons 主役は 50〜200x に落ちる(確保が生きているから)」と書いた。
  実測は整数ループより上。外れた理由: **確保の大半が塔の側にある**と見抜けていなかった。
- ▲ 途中、cons 側が一度 tag 11 で止まったが、あれは反証ではなく **わたしの特殊化器の穴**(car/cdr/pair 未実装)。
  塞いで測り直した。**「止まった」を「限界だった」と書かない。**

🔴 **本当の壁は別のところにあった** —— 段F/G が cons 程式を**断る**。値が pair だと register にも
i64 スロットにも置けない。⇒ 七段目でここを崩した(§1-4)。

### 1-6. 🔴 合流 —— 姉妹実験 exp/03 の init.zig に載せた(九段目)

姉妹実験 `exp/03-wasm-userland`。**PID 1 になる init 兼 本物の WASI ランタイム**(4,367 行 Zig、
libc 無し・生 syscall)。ABI は最小 —— `env.print` を import、`run()` を export。**Futamura 三射影すべてを
literal に達成済み**で、`[cost] instrs= hostcalls= mempeak=` を **seed 固定で byte 一致**して刷る。

◆ **わたしの wasm は、書き直さずにそのまま載った**(一発。ABI が偶然でなく一致していた)。

| ROM | instrs(決定的) |
|---|---|
| `compiled`(sum 1..1000、100 B) | **17,017** |
| `probe_clos`(閉包、107 B) | **6,317** |

🔴 **そして八段で測れなかった A/B が、数になった**(計器なしの走行 = 費用の真値):

| 回収 | instrs | vs なし |
|---|---|---|
| なし | **53,859** | — |
| セル単位に返す | **65,859** | **+12,000 = +22.3%** |
| **まとめて捨てる(region)** | **53,939** | **+80 命令 = +0.149%** |

- **+80 は 20 回 × 4 命令**(束縛で hp を控える 2 + scope 出口で戻す 2)。**ぴったり一致する。**
- 同じ ROM を二度走らせて 53,939 / 53,939。**決定的。**
- ms の見立て(+20〜25% / 区別がつかない)と icount(+22.3% / +0.149%)は
  **ms が見えた所では一致し、見えなかった所を icount が解いた** —— 二つの計器が互いを検算した。

⚠️ **ここでも計器が測定を支配していた** —— 計器つきで測ると *回収した方が命令が少なく* 出た
(hp が伸びないので「峰を更新する」枝が省かれる)。⇒ **峰を読む走行と費用を測る走行を分けた**(`--nopeak`)。
これで三度目 —— ms の揺れ / JIT の段 / 峰の計器。**秤は毎回、自分が測定を汚していないかから疑う。**

⚠️ **合流のとき門番が一本生えた**: init.zig は `if`(0x04)を持たない(実測「未対応 opcode 0x4 @body ── 育てる余地」)。
`block` + `br_if` + `i32.eqz` の形へ吐き直した(あちらが確実に持つ構造だけで書く)。
▲ **値を返す `if`(結果型つき block)はまだ吐けない** —— 現在の probe は使っていないが、境界として残る。

### 1-7. 🔴 A(P) —— 底までの距離は、解釈の軸ではゼロだった(十段目)

**予想は撃つ前に `symbolon/icount.sh` の頭へ書き、単独で commit してから測った**(秤 八条 #1)。

| ROM | byte-walk | **collapse = A(P)** | 比 |
|---|---|---|---|
| `compiled`(sum 1..1000) | 17,017 | **17,016** | 1.00006 |
| 回収なし | 53,859 | **53,818** | 1.0008 |
| セル単位に返す | 65,859 | **65,818** | 1.0006 |
| まとめて捨てる(region) | 53,939 | **53,898** | 1.0008 |

⚠️ **予想① は外れた** —— 「byte-walk : collapse は 2〜10x」と書いた。**実測 ≈ 1.0**。
🔴 **外れ方が答えだった**: **わたしの出力には畳む塔が無い。** exp/03 の A(P) は「interp 層を畳んだ後に
残る底」で、わたしの wasm は *程式* であって interpreter ではない ∴ **既に底に居る**。
畳んでも 41 命令(block/end 等の構造)しか減らない。
⇒ **これは段E(特殊化)が塔を畳み切っていたことの、外の計器による裏取り**。§1-2 の「407 分の 1」に底が付いた。

- ✅ **予想②③ は当たった** —— 所有の代金は **底でも同じ**:
  ΔA(region) = 53,898 − 53,818 = **+80**(byte-walk と 1 命令も違わない)/ ΔA(セル単位) = **+12,000**。
  ⇒ **回収は「解釈の厚み」ではなく「本当の仕事」。畳んでも消えない。** そして +80 は 20 回 × 4 命令のまま。

▲ **単位の線**: `instrs` は *op の数* で cycle ではない。⇒ 「底」の意味は
   **「解釈を減らして op を減らす余地はもう無い」**であって、「もっと速くできない」ではない。
   より良い codegen が *吐く op 自体* を減らす余地は残る(段F の 13x 負けと同じ軸)。
◆ **高さ非依存を撃った**(四十五段) —— 十段から開いていた ▲ を閉じた。`compiled.wasm` を P にして
   interp の塔を建て、**各層が自分で吐く `[cost]` を読む**(一番内側が P の底値):

| 高さ | P の底値 | 中 | 外(native が塔ごと回した総 dispatch) |
|---|---|---|---|
| h=1 (interp 1 層) | 17,017 | — | 17,017 |
| h=2 (interp 2 層) | 17,017 | — | 12,140,870 |
| h=3 (interp 3 層) | 17,017 | 12,140,870 | 9,263,369,734 |

🔴 **底値は高さに依らない。** しかも h=3 の中段は h=2 の外と一つも違わない
   ⇒ **一段積んでも、下の塔は動かない。** 一層の乗算 k = 713.5 / 763.0(h=3 は h=1 の 544,360 倍)。
   collapse A(P) = 17,016 ⇒ 底値との差は構造 op の分だけ。
▲ **答えの一致は撃てていない** —— わたしの ROM は自給で `env.print` を import しない ∴ 出力は全高さで空。
   一致しているのは **命令数**であって、値ではない。あちらの門番は錨①(出力恒等)を byte で張れるが、
   それは向こうの ROM が print を import しているから。⇒ **自給の代価**をここに書いておく。
※ あちらは h=3 で「メモリの壁(OutOfMemory)」に当たると書いている。こちらは完走した ——
   ROM が小さく塔が 189 KB に収まるため。**あの壁は設計の壁ではなく、大きさの壁**だった。

**建てた門**: `symbolon/tower.sh` —— 塔を建て、各層の `[cost]` が揃うことを **在で** 判定して
`[TOWER ok]` を出す（動いたら `⛔` で 1 を返す）。⚠️ 「落ちなかった」では読まない。
※ `compiled.wasm` が 91→100 B になったのは `kernel` export(A(P) を測る口)を足したため。

```bash
ERIS_EXP03=…/exp/03-wasm-userland bash symbolon/icount.sh   # 底値と A(P)
ERIS_EXP03=…/exp/03-wasm-userland bash symbolon/tower.sh    # 塔を h=1/2/3 で建てて高さ非依存
```
※ **写さず指す**(ptyx の `scripts/rom/probe.sh` と同じ作法)。姉妹実験が無ければ正直に skip する。

### 1-4. 🔴 壁を崩した —— 段G′: pair を線形メモリへ(七段目)

**やったこと**: tag も boxing も足さず、**値の形を静的に推した**。
`Kind = Int | List`(List = nil か *int の list*)を컴パイル中に伝播させ、形が決まらなければ **断る**。
形が分かれば表現は要らない —— **int は生の i64、list は番地(nil = 0)**。
`cons` は bump heap に 16 B 積み、`car`/`cdr` は `i64.load` offset 0/8、`is_pair` は `≠ 0`。

| 程式 | 段E(特殊化命令列) | **段G′(wasm)** | 成果物 | 床D 比 |
|---|---|---|---|---|
| cons が主役 | 0.0185 ms | **0.00068 ms** | **226 B** | ≈**17,800x** |
| 閉包が主役 | 0.0107 ms | **0.00012 ms** | **107 B** | ≈**60,000x** |

## 2. 二つの芯

**(a) 「減らす」と「低くする」は別の軸。** 減らす(塔を畳む)= 命令 **407〜426 分の 1**、
低くする(x86)= **7〜11x**、低くしすぎて判断を失うと **13x 損**。◆ これが 変態五十九 の「Futamura 一段目 1.1x」を説明する ——
あの時の特殊化先は**また AST** で、命令数が減っていなかった。
🔴 **低くすることは情報を増やさない。情報を使ってくれる層を取り除くだけ。**

**(b) 「アセンブラなのになぜ」は謎ではない。** 機械語は**形式**であって速さの性質ではない。速さを決めるのは
*判断*。段F は判断を一つもしていない(スタック機械の逐語訳)ので、吐いた命令列で **1 反復あたりメモリ操作 28 回**。
実測 16 cycles はそれでほぼ全部説明がつく。本当の仕事は **4 ALU 命令**だけ。
⇒ **「wasm がアセンブラに勝った」のではない。「コンパイラが逐語訳に勝った」。**
▲ 反証: 段F に割付を入れて 0.5 ns 付近へ落ちれば確定(未実施)。

**では、なぜアセンブラを吐くのか** —— **依存ゼロ**(102 B。LLVM を要求するコンパイラは*種になれない*)/
**理解**(意図と珪素の間に何も挟まらない)/ **埋め込み可能**。Zig の self-hosted backend も Jai も、
理由は実行速度でなく**独立性とコンパイル速度**だった。
🔴 **速さが欲しいなら wasm が既定でいい。** 手で吐く価値は「LLVM に割付で勝つ」ことではなく、
**「汎用 backend が導出できない情報を渡す」**こと。その情報が **所有**(§5)。

## 3. 接点 —— engine seam(段H。既存の Web / アプリ開発へ)

◆ **設計の線: 言語に HTML も DOM も足さない。** melon engine が既に形を持っている(状態は言語 /
入力は source 非依存の event / 出力は projection)= そのまま web の形。
⇒ **web 開発は projection を DOM にするだけ**で言語側は不変。実績: melon 不変で canvas 2D → 素の WebGL を差し替えた。

**実物**: kokkos 側で副作用の無い step 式を二本組み、状態を **wasm の線形メモリ**に置いて
`step(i64)->i64` と `memory` を export(**159 B**)。JS は `BigInt64Array` で読むだけで**規則を一行も持たない**。
秤(三点): **kokkos の機械が出した真値の軌跡** ⟷ node の毎歩再演 ⟷ **実 Chromium の本物の DOM クリック 18 回**。
**接点そのものはデータで置いた** → `engine_seam.json`。framework を一つも要求しない。

◆ **段H も決定的計器に載った**（四十六段）—— ここには長く「`engine.wasm` は合流の列に入れられない
（export が `step`/`memory` で、あちらの入口は `run`）」と書いてあった。▲ **入れ方が一つではなかった。**
seam に `run` を足すのは *測りたいから公開の約束を広げる* ことで **順序が逆** ⇒ seam は一 byte も
動かさず（`engine.wasm` は 159 B のまま）、**同じ body から**駆動つきの `engine_probe.wasm` を吐いた。
軌跡は Python 床が出した真値をそのまま焼く ⇒ **期待値をどこにも書き写していない。**

| 何 | 値 |
|---|---|
| `engine_probe.wasm` | 256 B / 軌跡 18 歩 |
| 決定的な命令数 | 952 |
| 姉妹実験が返した最終 total | 6 ← Python 床の真値と一致（threaded / byte 歩行の両路で） |

⚠️ `engine_probe` は **seam ではない** —— export は `run`/`kernel` だけで `step`/`memory` を名乗らない。
名を重ねると読み手が接点と取り違える。⇒ 測る物と渡す物を、名前の層で分ける。

**建てた門**: 吐き口が `[ENGINE-ROM ok]` を出す —— 軌跡の歩数と期待 total を **素材から読んで**印にする。
⚠️ 素材が無い日は黙って飛ばさず落ちる（`engine_trace.json が要る`）。不在で静かに通らない側。

```
                    ┌→ x86-64 native (102 B)   ← 依存ゼロ・埋め込み(種)
特殊化命令列 ───────┼→ wasm (100–226 B)        ← 既定。速く、ブラウザが付いてくる
                    ├→ 自己完結 HTML (2.6 KB)   ← wasm を base64 で抱えるだけ
                    ├→ engine seam (159 B)     ← **既存 web / app はここに繋ぐ**
                    └→ polyglot PNG            ← #5 が実証済み
```

🔴 **「見かけ上 HTML が出てくる」は *配布形式* の話であって、言語の性質ではない。**
◆ `ev` は人のクリックでも agent の判断でも同じ形で届く ⇒ **同じ seam が web アプリにも agent 駆動にも使える。**

## 4. 所有は何のライセンスか —— 五度の訂正を経て、初めて条件が通った

| 段 | 主張 | 判定 |
|---|---|---|
| 一 | 所有は**速さ**のライセンス(残費用は refcount) | ❌ 外れ(Rc 外しは 1.1x) |
| 二 | 所有は**常駐**のライセンス | 半分だけ当たり |
| 三 | 有界性の道は三つ(GC / 所有 / **静的な死**)。一番安いのは三番目 | ✅ 当たり |
| 六 | 所有が要るのは **backend が値を置けるようにするため** | 当て先は合っていた |
| 七 | 仕事は「形」と「寿命」に割れる。**形は型推論で足りた** | ✅ 壁は形だけで崩れた |
| **八** | **寿命は所有にしか出せない。そして region で取れば費用は測れない** | ✅ **条件が通った(五度目にして初めて)** |

🔴 **結論**: **所有は速さを買わない。買うのは *有界性* —— 走り続けられること。**
そして **その代金は、まとめて捨てる形なら測定の揺れに埋もれる**(セル単位で返すと +20〜25% 払う)。
二段目の「常駐のライセンス」が、六段・七段を回って**測れる形**で戻ってきた。

◆ **設計として言えること**: 所有の出しどころは *解放の命令* ではなく **region の境**。
コンパイラに要るのは「この値はいつ死ぬか」ではなく「**この scope で生まれた物は、この scope で全部死ぬか**」。
前者は難しく、後者は `scan_owned` 程度の走査で言える —— **安い問いに置き換えられる**のが所有の値打ち。

▲ 反証条件(次): ① 入れ子 region / 複数の所有 list で費用が線形に増えないか
   ② region に収まらない寿命(scope をまたいで生きる list)が出た時、何が要るか。

### 推し ⑤ —— 値を返す `if` と、言語 → host

◆ **理由**: §3 で通したのは **host が言語を駆動する向きだけ**。既存の web / app へ繋ぐ話が
そこで半分止まっている。しかも `if` の型検査は三十七段で触ったばかりで、手が温まっている。

⟨撃つ前の予想⟩ ※ 外れたら、外れた向きまで記録する（この repo の作法）
- 値を返す `if`（結果型つき block）は **吐く側ではなく受け側で詰まる** —— 九段の実測で
  init.zig は `if`(0x04) を持たなかった。⇒ 落ちるなら姉妹実験の側。あちらが受けたら外れ。
- 言語 → host は **門ではなく看板とぶつかる**（撃って確かめた）—— `[NOIMPORT ok]` は段G の
  吐き出しが自分の module を走査して出す印で、import を足せば `⛔ 自給が崩れた` で止まる。
  seam 側にだけ入れれば門はその場では鳴らないが、**公開の「imports nothing」は木全体の主張**。

~~🔴 決めるのは技術ではない —— 自給を看板として残すか、seam の双方向を取るか。~~
**建てた門**: 吐いた module の code 節を歩いて `[NO-IFOP ok]` を出す。⚠️ これは *不在* を根拠にする
主張 ⇒ **在ることを要る印へ裏返した**（`NOIMPORT` と同じ向き。二十三段の型）。知らない opcode に当たったら
「無い」ではなく **測れない** で落ちる —— 黙って 0 を返すと *壊れた走査* と *本当に無い* が同じ答えになる。
◆ module を組む **二つの口の中**に置いた ⇒ 印を出し忘れられない（宣言を使用から導く。二十六段の型）。
✅ **受け側で撃った**（2026-09-07、四十五段）—— `icount.sh` の `probe_join` の行が、置いた翌日に初めて
火を吹いた。`instrs=140 hostcalls=0`、trap も「未対応 opcode」の叫びも無し ⇒ **block 二枚に書き直した
値位置の `if` は、本当にあちらを通る。** ⚠️ 受け側は未知 opcode を黙って飛ばさない（threaded は
`error.UnsupportedOp`、byte 歩行は停止）⇒ 「通った」は「見逃された」ではない。

✅ **決着: 自給を残す**（2026-09-06、指示「推しで行こう」）⇒ **言語 → host は取らない。**
二十九段の型どおり、入口の「できないこと」を書いた一行は *働いている*（外から読ませたら
本当にそう返ってきた）⇒ 黙って外さない。**要る日が来たら、外したと名乗ってから外す。**
