## 1. 誰のための物か —— agent-first

🔴 **一次利用者はエージェント。** これは願望でなく、この九段が実際にそう動いたことの記述。

- backend は五つとも、**言語の実装を一行も読まずに**書かれた(読んだのは契約データと tag 表だけ)。
- 姉妹実験 exp/03 との合流も、ABI が **書き直しゼロで一致**した。
- 実行時も同じ —— engine seam の event は「人のクリックでも agent の判断でも同じ形で届く」。

**帰結(設計に効く形で)**:

1. **契約は散文でなくデータで置く。** エージェントは散文を守れない。データなら守れる。
2. **要件には *確かめ方* を付ける。** 「べき」でなく述語。走らせて真偽が出る形。
3. **小さい言語がエコシステムで死ぬ、の前提が弱まる。** 読み手がエージェントなら、
   ライブラリも IDE も「無いから死ぬ」ではなく「その都度書ける」に変わる。
   ※ これは見立て。反証: エージェントに書かせても実用に届かない領域が出たら弱まる。

## 2. 要件 —— 各条項に「強制したもの」と「反証条件」

> ⚠️ 網羅していない。**実測が強制した分だけ**書く。増やすときも同じ規律で。

### R1. 契約はデータで書かれていること
- **強制したもの**: 段E〜H を、melon / kokkos / ptyx を一行も触らずに書けた。exp/03 と一発で噛んだ。
- **反証**: 新しい backend を足すのに **言語側の実装を触る必要が出たら**、この要件は満たされていない。
- **確かめ方**: backend を足した diff に `melon/` `koinon/` `experiments/third/kokkos.py` が現れないこと。

### R2. どの段も「同じ答え」を機械が確かめてから次へ進むこと
- **強制したもの**: 四床 differential / 実 Chromium / 真値の軌跡。写しの腐りを三度この形で捕まえた。
- **反証**: 秤を通さずに出した数字は無効。⚠️ **実際に三度、通さずに出した見立てが外れた。**
- **確かめ方**: 各門番が `exit 1` を持つこと。緑が並ぶことと最後まで走ったことを混同しない。

### R3. 語るのは決定的な量であること
- **強制したもの**: ms が走行間で ±40% 動いた / JIT の段が測定を支配した / **計器自身が測定を汚した**(三度)。
- **単位**: 命令数・確保数・バイト数・icount(exp/03 の `[cost] instrs=`)。**ms は同一走行内の比だけ。**
- **反証**: 分布が重なったら「区別がつかない」と書く。**跨いだ ms を根拠にしたら違反。**
- **確かめ方**: 同じ ROM を二度走らせて同じ数が出ること。

### R4. 速さは「塔を畳む」ことで取る
- **強制したもの**: 塔(解釈の厚み)が三桁、床の実装が一桁、native 化が一桁。**足しても届かない。**
- **⇒ 設計判断は一行**: **コンパイルできる形で言語を設計する。**
- **反証**: 値の種類を変えて三桁が崩れたら前提が崩れる。⚠️ **六段で撃って、崩れなかった**(整数 / 閉包 / cons)。

### R5. 言語に host を足さないこと(HTML / DOM / syscall)
- **強制したもの**: engine seam が言語不変で成立した。melon 不変で canvas 2D → 素の WebGL を差し替えた実績。
- **形**: 状態は言語が持つ / 入力は **source 非依存の event** / 出力は **projection**。
- **反証**: DOM や syscall を触るために **object 層に節を足す必要が出たら**違反。
- ▲ 現在ここは半分だけ実測(host → 言語の向きのみ。言語 → host は §6)。

### R6. 所有は「寿命」を渡すために在る(速さのためではない)
- **強制したもの**: refcount 外しは効かなかった / **形は静的な型推論で足りた** / 寿命だけが残った。
- **形**: 所有が出るのは *解放の命令* ではなく **region の境**。
  要るのは「いつ死ぬか」でなく「**この scope で生まれた物はこの scope で全部死ぬか**」。
  ⇒ **難しい問いを安い問いに置き換える**のが所有の値打ち。
- **反証**: region 回収の費用が定数倍を超えたら / 揃わない条件が普通になったら。
- ⚠️ **この条項は四度書き換わっている。** 経緯は `COMMON.md` §4。

### R7. 出力は選択肢であること(配布形式は言語の性質ではない)
- **強制したもの**: 一つの特殊化命令列から native / wasm / 自己完結 HTML / engine seam が出た。
- **反証**: 出力先を増やすのに **front-end を変える必要が出たら**違反。

### R8. 新しい backend を、契約だけ読んで書けること
- **強制したもの**: 実際にそうなった(五つ)。これが R1 の *利用者側から見た* 姿。
- **受け入れ条件**: §5 を参照。**「読む物」が契約データに閉じていること。**

## 4. 基本設計

### D1. 層 —— 三つに割る

```
front-end(符号化)      … 表層 → object-data。⚠️ Python のまま。別の portability surface
     ↓  ★契約(データ)★  … ここだけが共通。14-op / 値モデルの整数域 / object tag 表 / engine seam
back-end(複数)         … 命令列 / x86-64 / wasm / wasm+heap / engine seam
     ↓
実行基盤               … V8 / 自前 mmap 頁 / **exp/03 の init.zig**(PID 1・WASI・決定的計器)
```

◆ **共通にするのは実装ではなく契約と検証。** 実装は複数あってよい(現に床は 4 + 段が 6)。
◆ 各言語の *身元*(所有が何を所有するか)は契約に入れない。**契約がデータで書けるものは共通、身元が語るものは各家。**

### D2. 契約 —— データで置く四つ

| 契約 | 実体 | 版が切れるか |
|---|---|---|
| 実行の op | `machine.json`(14-op) | ✅ データ。**版と指紋は `contract.lock`** |
| 値モデルの整数域 | `cases.json` の overflow 行が番人(f64 2^53 < i64 2^63 < bignum ∞) | ✅ 表に出ている |
| object の節 | `enc_expr` の tag 表 | ✅ 表 |
| host との seam | `engine_seam.json`(abi / exports / スロット表 / 読み方) | ✅ データ |

⚠️ **契約を変えるときは版を切る。** 黙って広げない。

### D3. 秤 —— 八条(エージェントの操作規律)

1. 予想は**撃つ前に**書く　2. 決定的な量で語る　3. ms を跨いで比べない　4. 温めてから測る
5. 速すぎたら疑う(線形性)　6. 分布が重なったら「区別がつかない」と書く
7. **計器が測定を汚していないか毎回疑う**　8. **「止まった」を「限界だった」と書かない**

◆ 門番の配置: `cases.json`(実装間) / `probe_run.mjs`(実走 + 線形性) / `web_verify.mjs`・`engine_verify.mjs`
(実ブラウザ) / **`icount.sh`(決定的 icount。姉妹実験を *写さず指す*)** / **`tower.sh`(塔を h 段積む)**。
▲ 八条はどれも **この期間に自分が踏んだ失敗から生えた**。借り物ではない ∴ 外すときも実測で。

### D4. 出力面 —— 一つの命令列から

```
特殊化命令列 ─┬→ x86-64 native   … 依存ゼロ・埋め込み(種)
              ├→ wasm            … 既定(速く、ブラウザと init.zig の両方が付いてくる)
              ├→ 自己完結 HTML   … wasm を base64 で抱えるだけ = *配布形式*
              ├→ engine seam     … 既存 web / app はここに繋ぐ
              └→ polyglot PNG    … #5 が実証済み
```

### D5. 所有の在処

| 渡す情報 | 誰が出せるか | 何に要るか |
|---|---|---|
| **形**(int か list か) | 静的な型推論で足りる(**所有は要らなかった**) | 値を register / 線形メモリに置く |
| **寿命**(この scope で全部死ぬか) | **所有にしか出せない** | heap を有界にする = 走り続けられる |

### D6. 合流点 —— 単位を揃える

exp/03 = 実行基盤(PID 1 / WASI / 決定的 icount / A(P))。こちら = コンパイル層。
🔴 **両者の単位は `instrs` で揃う** ∴ 「capability を行使する費用」と「所有が heap を有界にする費用」が
**同じ式に入る**。どちらの家も単独では持てない量が、ここで出る。
※ 依存は **pointer**(`ERIS_EXP03`)。写さない。無ければ門番は正直に skip する。
